# `data/` - where the inputs go

Nothing in this directory is searched by name from code. Every input is
addressed by its *logical name* and resolved by `repro.config.path()`, which
searches, in order:

1. `$MARINE_REPRO_DATA` (if set),
2. every entry of `paths.data_roots` in `config/config.yaml` (`data/`, `data/shipped/`),
3. `outputs/` (so a stage can consume an earlier stage's product).

Each root is searched recursively, so the layout inside `data/` is up to you.

## What ships inside this package

`data/shipped/` holds every result table small enough to redistribute - the
benchmark summaries, significance tests, control-experiment tables, the
screening funnel, the consensus feature table and the network tables. That is
what makes `stages/stage12_verify.py` runnable the moment you unpack the
module, with no download at all.

## What you must obtain

`config/inputs_manifest.tsv` is the authoritative list. Columns:

| column | meaning |
|---|---|
| `logical_name` | the name code asks for |
| `size_bytes`, `sha256` | verify your copy with `shasum -a 256` |
| `origin` | where it comes from |
| `produced_by_stage` | which stage of this module regenerates it |
| `ships_in_package` | `yes` if it is already in `data/shipped/` |

Rows with `ships_in_package = no` fall into three groups.

**1. Study data products (~173 MB, 21 files).** The curated marine library, the
ChEMBL label matrix, the decoy set, the applicability-domain table, the model
bundle, the SHAP tensors and the scored marine library. Every one of them is
regenerated by the stage named in `produced_by_stage`, so they are a
convenience, not a dependency: a reader who runs stages 1-8 produces them. They
are also deposited alongside the paper; download the deposit and unpack it into
`data/`.

**2. CMNPD vendor files (not redistributable).** `CMNPD_1.0_calc_prop.tsv` and
`CMNPD_1.0.sdf` are the Comparative Marine Natural Products Database release
files. The licence does not permit redistribution. Register at
<https://www.cmnpd.org>, download release 1.0, and place both files anywhere
under `data/`. Only stages 2 and 3 need them.

**3. Live API data.** Stages 1, 3 and 4 fetch from Open Targets, CIViC, STRING,
Reactome, QuickGO, ChEMBL and ZINC20 at run time. Those services evolve; a
re-fetch today will not return byte-identical records to the original run. The
cached JSON responses from the original run are in group 1 above, and the
stages prefer them when present - which is what makes the pipeline
deterministic. Delete them to force a live re-fetch.

## Checking what resolves

    ./run_all.sh --check

prints, stage by stage, which inputs are found and which are missing.
